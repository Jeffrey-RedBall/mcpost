# mcskill，把作業變成 Skill

方向跟其他 /mc 指令相反：不是從 MakeClass 拿東西，而是把**使用者剛做完的事**留下來。

## 步驟

1. 回頭讀這一輪對話，找出**可重複的流程**：什麼情況會用到、做了哪幾步、哪些地方容易出錯、成功的標準。沒有明顯的流程就老實說，問使用者要存哪一段。
2. 寫成 SKILL.md 草稿：
   ```
   ---
   name: <小寫英數與連字號>
   description: <做什麼＋什麼時候觸發，含使用者可能會說的幾句話>
   ---
   # 標題
   ## 什麼時候用
   ## 步驟
   ## 注意事項（踩過的坑）
   ```
3. **清掉不該留下的**：API key、token、密碼、客戶名稱與聯絡方式、內部網址、個人資料。換成「<某客戶>」「<金鑰>」這類佔位。清不乾淨的就整段拿掉，並告訴使用者拿掉了什麼。
4. 把草稿完整呈現給使用者，問兩件事：
   - 存在哪裡：這個專案（`.claude/skills/<name>/SKILL.md`），或全域（`~/.claude/skills/<name>/SKILL.md`）
   - 要不要同時存一份進 MakeClass 的**私人**工具箱（之後在任何電腦都查得到）
5. 使用者確認才寫檔。目標已存在就先問，預設不覆蓋。
6. 選了存進工具箱才執行（只有本人看得到，要公開得自己到網頁改）：
   ```bash
   mcpost call collect_skill '{"name":"<name>","category":"Claude Code Skill","purpose":"<一句話>","note":"由 /mcskill 從作業整理"}'
   ```
   這需要權杖有「發表內容」權限；沒有就說明，檔案已寫好不受影響。

## 不要做

- 不要自動公開、不要發文。MakeClass 的公開 Skill 庫只收 YouTube 影片來的，自己的作業只會進私人工具箱。
- 使用者沒確認之前不要寫任何檔案。
