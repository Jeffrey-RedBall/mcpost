# mcidea，存靈感、看靈感

跟 LINE 打「靈感：」、網頁收件框是同一個地方：網頁「知識庫 → 💡 靈感」看得到。

## 先判斷這次要做什麼

只看 `/mcidea` 後面**第一個字**：

| 第一個字 | 做什麼 |
| :--- | :--- |
| 沒有任何內容，或 `help` | 顯示下面「用法」，**不要存任何東西**，也不要反問 |
| `list` | 列出靈感（唯讀），見「列出」 |
| 其他任何內容 | 存成新靈感，見「存」 |

使用者真的要存一則以 help 或 list 開頭的靈感，會寫成 `/mcidea 靈感：help 文件要改`，開頭是「靈感：」就是內容，照存。

## 用法（原樣顯示）

```
/mcidea <靈感>                  存一則靈感（原文照存，私人）
/mcidea 專案:<名稱> <靈感>       存並歸到某個專案
/mcidea list                    列出全部靈感
/mcidea list 進行中              只看某個狀態（待評估／進行中／完成／放棄）
/mcidea list 專案:<名稱>         只看某個專案
/mcidea list <關鍵字>            依專案名或文字比對
/mcidea help                    顯示這段
```

## 存

1. 取 `/mcidea` 後面的內容當靈感。**原文照存，不要改寫、不要潤飾、不要補充你的想法。**
2. 使用者有寫 `專案:<名稱>` 才帶 `project`；沒寫就不帶，不要自己歸類。
3. 存：
   ```bash
   mcpost call save_idea '{"text":"<靈感原文>","project":"<專案，沒有就不要這個欄位>"}'
   ```
   文字裡有引號或換行，要正確跳脫成 JSON。
4. 回報**一行**：「已存進靈感存放區（只有你看得到）：<標題>」＋連結。
5. 回傳 `error`：含金鑰或密碼 → 轉述原因，請使用者移除後再存，**不要自己幫他改內容重送**；太長 → 請他縮短或分成幾則；沒有權限 → 說明權杖需要「發表內容」權限。

## 列出（唯讀）

1. 狀態對照：待評估＝`inbox`、進行中＝`doing`、完成＝`done`、放棄＝`dropped`。
2. 查：
   ```bash
   mcpost call list_my_ideas '{}'
   mcpost call list_my_ideas '{"status":"doing"}'
   mcpost call list_my_ideas '{"project":"<專案名>","query":"<使用者原句>"}'
   ```
   `list` 後面不是狀態也不是 `專案:` 的字，當關鍵字放進 `query`。
3. 依狀態分組列出，每則：標題或前一行、專案、連結。**每一則都要列到**（最多 40 則），結果有幾則就講幾則，不要省略。
4. 沒有就說「這個條件下沒有靈感」。要改狀態或歸專案，請他到網頁「知識庫 → 💡 靈感」。

## 不要做

- 不要存使用者沒叫你存的內容（對話裡出現一個點子不算）。
- 不要發布、不要公開，也沒有這個選項：靈感預設且只能是私人。
- 要把靈感做成文章或簡報，是之後在網頁用「轉成」做的，不在這裡。
